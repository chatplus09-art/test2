CHAPITRE 01

C'est quoi ce stage ?

Tu vas faire un stage sur l'IA agentique alors que tu viens des réseaux. Pas de panique — voilà exactement ce que ça veut dire, et ce qu'on attend de toi.

contexteobjectifsvocabulaire

Ce que tu vas faire concrètement

Ta fiche de poste parle d'IA agentique. En clair : tu vas aider l'entreprise à créer des petits programmes intelligents qui peuvent prendre des décisions et faire des actions à leur place — comme envoyer des emails automatiquement, lire des documents, chercher des infos sur internet, etc.

Tout ça sera codé en Python, et tu utiliseras des LLMs (comme ChatGPT, Claude…) comme cerveau central.

💡
Rassure-toi

Tu n'as pas besoin d'être un expert en machine learning ou en maths avancées. L'IA agentique c'est 90% du développement Python qui utilise des APIs. Avec ta formation BUT RT tu as déjà des bases solides en réseau et en programmation — c'est largement suffisant pour commencer.

Le vocabulaire clé — ton lexique de survie

Avant tout, voilà les mots que tu vas entendre chaque jour. Pas besoin de les mémoriser maintenant, reviens ici si tu oublies.

LLM (Large Language Model)
Un programme d'IA qui comprend et génère du texte. ChatGPT, Claude, Mistral en sont des exemples. Pense à une calculatrice ultra-puissante qui calcule des mots au lieu de chiffres.
Agent IA
Un LLM auquel on a donné des outils pour agir (chercher sur le web, lire des fichiers, envoyer des mails…). C'est la différence entre un expert qui donne des conseils et un assistant qui exécute vraiment les tâches.
API (Application Programming Interface)
Tu connais déjà ça depuis le BUT RT ! C'est simplement un moyen pour deux programmes de se parler. L'API d'Anthropic te permet d'utiliser Claude dans ton code Python.
Prompt
Le texte que tu envoies au LLM. C'est ton "message" au modèle. La qualité de ta réponse dépend beaucoup de la qualité de ton prompt.
Token
L'unité de mesure des LLMs. À peu près 4 lettres ou ¾ d'un mot. "Bonjour" = 1 token. Les LLMs coûtent de l'argent par token — important à surveiller !
RAG (Retrieval-Augmented Generation)
Technique qui permet à un LLM de chercher dans une base de documents avant de répondre. Sans ça, le LLM ne connaît que ce sur quoi il a été entraîné (pas tes documents d'entreprise).
Framework
Une boîte à outils prête à l'emploi. LangChain est un framework IA : au lieu de tout coder de zéro, tu utilises ses outils. Comme utiliser React au lieu de recoder un framework web.

La gestion d'erreurs — indispensable avec les APIs

Les APIs plantent. Le réseau coupe. Le LLM dépasse sa limite de débit. Tu dois gérer ces erreurs dans ton code sinon ton agent va crasher au premier problème.

python — gestion_erreurs.py
import time

def appeler_api_avec_retry(prompt: str, max_tentatives: int = 3) -> str:
    """Appelle une API et réessaie automatiquement si ça échoue."""

    for tentative in range(max_tentatives):
        try:
            # Ce qui peut échouer est dans le try
            reponse = appeler_llm(prompt)  # ← peut lever une exception
            return reponse  # si ça marche, on retourne directement

        except ConnectionError as e:
            # Erreur de connexion réseau
            print(f"❌ Tentative {tentative + 1} échouée : {e}")

            if tentative < max_tentatives - 1:
                delai = 2 ** tentative  # 1s, 2s, 4s... (backoff exponentiel)
                print(f"⏳ Nouvelle tentative dans {delai}s...")
                time.sleep(delai)
            else:
                print("❌ Toutes les tentatives ont échoué.")
                raise  # on re-lève l'exception pour alerter l'appelant

        except Exception as e:
            # Toute autre erreur inattendue
            print(f"🔴 Erreur inattendue : {e}")
            raise
⚠️
Erreur classique de débutant

Ne jamais faire except: pass — ça avale l'erreur silencieusement. Tu ne sauras jamais que quelque chose s'est mal passé. Toujours au minimum faire un print ou un raise.

Classes & Organisation du code

Les classes permettent de structurer son code. Dans les projets IA, tout est organisé en classes : agents, outils, configurations. Voici comment ça marche, expliqué simplement.

classobjethéritagePydantic

Qu'est-ce qu'une classe ?

🖨️ Analogie — le moule et les objets

Imagine une classe comme un moule à gâteau. Le moule définit la forme (les attributs et méthodes). Chaque objet (ou instance) est un gâteau créé à partir de ce moule — ils ont tous la même structure, mais des données différentes (vanille, chocolat…).

python — classes_intro.py
# Exemple concret : modéliser un "Outil" pour un agent IA

class Outil:
    """Représente un outil que peut utiliser un agent IA."""

    def __init__(self, nom: str, description: str):
        # __init__ est appelé automatiquement quand on crée un objet
        # "self" représente l'objet lui-même
        self.nom = nom
        self.description = description
        self.nb_utilisations = 0   # compteur interne

    def executer(self, entree: str) -> str:
        """Exécute l'outil sur une entrée."""
        self.nb_utilisations += 1
        # À surcharger dans les sous-classes
        raise NotImplementedError("Chaque outil doit implémenter executer()")

    def __str__(self) -> str:
        # S'affiche quand on fait print(mon_outil)
        return f"Outil[{self.nom}] — {self.description}"


# Une classe enfant qui HÉRITE de Outil
class Calculatrice(Outil):  # ← hérite de Outil
    def __init__(self):
        # super() appelle __init__ du parent (Outil)
        super().__init__(
            nom="calculatrice",
            description="Calcule des expressions mathématiques"
        )

    def executer(self, entree: str) -> str:
        # On surcharge la méthode du parent
        try:
            resultat = eval(entree)
            return f"Résultat : {resultat}"
        except Exception:
            return "Erreur dans l'expression"


# Utilisation
calc = Calculatrice()          # créer un objet (instance)
print(calc)                      # Outil[calculatrice] — Calcule des expressions...
print(calc.executer("2 + 3"))   # Résultat : 5
print(calc.executer("10 * 4"))  # Résultat : 40
print(calc.nb_utilisations)     # 2 (compté automatiquement !)

Pydantic — valider ses données automatiquement

Pydantic est une bibliothèque qui permet de créer des classes "intelligentes" qui vérifient automatiquement que les données sont du bon type. C'est quasi-indispensable dans les projets IA car les APIs LLM renvoient des données qu'il faut valider.

python — pydantic_intro.py
from pydantic import BaseModel, Field

# Classe Pydantic pour structurer la config d'un agent
class ConfigAgent(BaseModel):
    """Configuration d'un agent IA."""
    modele: str = "claude-3-5-haiku-20241022"   # valeur par défaut
    temperature: float = Field(default=0.7, ge=0.0, le=2.0)  # entre 0 et 2
    max_tokens: int = Field(default=1024, gt=0)  # strictement positif
    verbose: bool = False

# ✅ Utilisation normale
config = ConfigAgent(modele="claude-3-5-haiku-20241022", temperature=0.5)
print(config.temperature)   # 0.5

# ❌ Pydantic valide et lève une erreur claire
try:
    mauvaise_config = ConfigAgent(temperature=5.0)  # > 2.0 → erreur!
except Exception as e:
    print(e)  # "temperature: value must be less than or equal to 2.0"

# Convertir en dict ou JSON facilement
print(config.model_dump())         # → dict Python
print(config.model_dump_json())    # → string JSON (pour les APIs)

Les appels LLM peuvent prendre 10 à 30 secondes. Async/await te permet de lancer plusieurs appels en même temps au lieu d'attendre l'un après l'autre. Et les APIs REST, tu en connais déjà le principe depuis le BUT RT !

Appeler une API — la base

Tu connais déjà les APIs depuis tes cours de réseau. En Python, on utilise la bibliothèque httpx (ou requests) pour faire des appels HTTP.

🌐 Analogie réseau — tu connais déjà ça !

Appeler une API LLM c'est exactement comme faire une requête HTTP POST que tu as appris en cours. Tu envoies un body JSON, tu reçois un body JSON en retour. Le seul truc nouveau c'est l'authentification par clé API dans les headers.

python — premier_appel_llm.py
import os
import httpx
from dotenv import load_dotenv  # pip install python-dotenv

# ⚠️ JAMAIS écrire la clé directement dans le code !
# On la stocke dans un fichier .env
load_dotenv()
MA_CLE_API = os.getenv("ANTHROPIC_API_KEY")

def demander_au_llm(question: str) -> str:
    """Envoie une question à Claude et retourne sa réponse."""

    # Les headers d'authentification (comme un token Bearer)
    headers = {
        "x-api-key": MA_CLE_API,
        "anthropic-version": "2023-06-01",
        "content-type": "application/json"
    }

    # Le body JSON de la requête POST
    body = {
        "model": "claude-3-5-haiku-20241022",
        "max_tokens": 512,
        "messages": [
            {"role": "user", "content": question}
        ]
    }

    # Envoyer la requête (timeout 60s car les LLMs sont lents)
    with httpx.Client(timeout=60.0) as client:
        response = client.post(
            "https://api.anthropic.com/v1/messages",
            headers=headers,
            json=body
        )

    # Vérifier que ça a marché (lève une exception si code >= 400)
    response.raise_for_status()

    # Extraire le texte de la réponse JSON
    data = response.json()
    return data["content"][0]["text"]

# Test
reponse = demander_au_llm("Explique-moi le RAG en 2 phrases")
print(reponse)

Async/Await — pourquoi et comment

Imagine que tu commandes 3 pizzas au téléphone. Sans async, tu appelles le premier, tu ATTENDS qu'il réponde, tu raccroches, tu rappelles le deuxième, tu ATTENDS… Avec async, tu passes les 3 commandes en même temps et tu attends que la dernière soit prête.

python — async_exemple.py
import asyncio
import anthropic

client = anthropic.AsyncAnthropic()  # version async du client

# Une fonction async se déclare avec "async def"
async def poser_question(question: str) -> str:
    """Version async : n'est pas bloquante pendant l'attente."""
    # await signifie "attends ce résultat sans bloquer les autres"
    reponse = await client.messages.create(
        model="claude-3-5-haiku-20241022",
        max_tokens=256,
        messages=[{"role": "user", "content": question}]
    )
    return reponse.content[0].text

# Lancer 3 questions EN MÊME TEMPS
async def analyser_plusieurs_textes():
    questions = [
        "Résume : 'Le RAG est une technique IA qui...'",
        "Traduis en anglais : 'Bonjour le monde'",
        "Donne 3 synonymes de 'rapide'"
    ]

    # gather() lance tout en parallèle et attend que tout soit fini
    resultats = await asyncio.gather(
        *[poser_question(q) for q in questions]
    )

    for i, resultat in enumerate(resultats):
        print(f"Q{i+1}: {resultat}")

# Lancer la fonction async depuis un contexte normal
asyncio.run(analyser_plusieurs_textes())

CHAPITRE 05

C'est quoi un LLM ?

Comprendre comment fonctionnent ChatGPT, Claude et compagnie — sans les maths. On s'intéresse à ce qui compte pour ton stage : comment les utiliser efficacement.

tokenscontextetempératurehistoriquestreaming

Comment ça marche, simplement

Un LLM (Large Language Model) est entraîné sur des milliards de textes. Son seul "talent" : prédire le mot suivant le plus probable. Mais à très grande échelle, cette capacité donne l'impression de comprendre et raisonner.

📶 Analogie réseau — autocomplete géant

Tu connais l'autocomplete de ton téléphone ? Il prédit le mot suivant. Un LLM fait la même chose, mais avec 200 milliards de paramètres au lieu de quelques millions, entraîné sur quasiment tout l'internet. Le résultat ressemble à de la "compréhension" mais c'est fondamentalement de la prédiction statistique très sophistiquée.

Les concepts clés à maîtriser

🪙 Les tokens — l'unité de base ▼

Un token ≈ 4 caractères, soit environ ¾ d'un mot. "Bonjour" = 1 token. "développement" = 2-3 tokens. Les espaces et ponctuations comptent aussi.

Pourquoi c'est important ? Les LLMs ont un coût par token. Claude Haiku coûte ~$0.001 pour 1000 tokens d'entrée. Un document de 10 pages ≈ 3000 tokens ≈ $0.003. Surveille toujours la consommation en développement !

Utilise platform.openai.com/tokenizer pour voir comment ton texte est découpé en tokens.

📦 La fenêtre de contexte — la "mémoire" ▼

Le LLM ne peut "voir" qu'un certain nombre de tokens à la fois — c'est la fenêtre de contexte. Claude 3.5 peut voir jusqu'à 200 000 tokens (~150 000 mots). GPT-4 : 128 000 tokens.

Très important : le LLM n'a aucune mémoire entre deux appels. Si tu envoies "Bonjour" puis dans un autre appel "Comment tu vas ?", il ne sait pas qu'il y a eu un premier message. C'est pour ça que dans les chatbots, on renvoie tout l'historique à chaque appel.

🌡️ La température — créativité vs précision ▼

La température (entre 0 et 2) contrôle à quel point le modèle prend des risques dans ses prédictions :

  • temperature = 0 : toujours la réponse la plus probable. Parfait pour extraire des données, classifier, analyser.
  • temperature = 0.7 : équilibre. Bon pour les conversations, explications.
  • temperature = 1.5+ : très créatif mais parfois incohérent. Pour la génération créative uniquement.

Pour les agents IA, utilise temperature=0 ou 0.2 — on veut des comportements reproductibles, pas surprenants.

📜 Le system prompt — les instructions permanentes ▼

Le system prompt est un message spécial envoyé avant la conversation, qui définit le comportement du modèle. C'est là que tu lui dis qui il est, comment répondre, dans quel format, etc.

exemple de system prompt
system = """Tu es un assistant expert en cybersécurité réseau.
Tu travailles pour une équipe de BUT RT.

RÈGLES :
- Réponds toujours en français
- Utilise des termes techniques précis
- Si tu ne sais pas, dis-le clairement
- Maximum 3 paragraphes par réponse"""

L'historique de conversation — crucial !

Comme le LLM ne se souvient de rien entre deux appels, c'est ton code qui doit maintenir l'historique et le renvoyer à chaque fois. Voici comment ça marche :

python — historique_conversation.py
import anthropic

client = anthropic.Anthropic()

# L'historique est une liste de messages qu'on ACCUMULE
historique = []

def chat(message_user: str) -> str:
    """Envoie un message et garde l'historique."""

    # 1. Ajouter le message de l'utilisateur à l'historique
    historique.append({
        "role": "user",
        "content": message_user
    })

    # 2. Envoyer TOUT l'historique au LLM
    reponse = client.messages.create(
        model="claude-3-5-haiku-20241022",
        max_tokens=512,
        system="Tu es un assistant pour stagiaires en BUT RT.",
        messages=historique  # ← on envoie tout, pas juste le dernier message
    )

    texte_reponse = reponse.content[0].text

    # 3. Ajouter la réponse du modèle à l'historique
    historique.append({
        "role": "assistant",
        "content": texte_reponse
    })

    return texte_reponse


# Test — le LLM "se souvient" grâce à l'historique
print(chat("Je m'appelle Lucas et je fais un stage en IA"))
print(chat("Quel est mon prénom ?"))
# → "Ton prénom est Lucas." (grâce à l'historique !)

CHAPITRE 06

L'IA Agentique

C'est le cœur de ton stage. Un agent IA peut prendre des décisions et exécuter des actions. Voici comment ça marche de A à Z, avec un exemple complet codé en Python.

agenttoolstool callingboucle agentique

LLM classique vs Agent IA

💬

LLM classique

Tu poses une question → il répond avec du texte. C'est tout. Il ne peut pas faire d'actions réelles dans le monde.

🤖

Agent IA

Tu poses une question → il décide quels outils appeler → ton code exécute les outils → il formule une réponse avec les vrais résultats.

🔧 Analogie concrète

Imagine un expert réseau très calé mais enfermé dans une pièce sans téléphone ni internet. Il peut te conseiller mais pas agir. C'est un LLM classique.

Maintenant donne-lui des outils : un terminal SSH, un accès au monitoring réseau, la liste des équipements. Il peut maintenant agir pour résoudre des problèmes. C'est un agent IA.

Le tool calling — le mécanisme central

C'est le concept le plus important à comprendre. Le LLM ne peut pas vraiment "exécuter" du code — il génère du texte qui décrit quel outil appeler. Ton code Python intercepte ça, fait vraiment l'appel, et renvoie le résultat.

1
Tu définis les outils disponibles
Tu envoies au LLM une liste d'outils avec leur nom, description et paramètres. Exemple : "get_weather(city: str)" ou "search_web(query: str)". Le LLM sait maintenant qu'il peut les "utiliser".
2
Le LLM décide d'appeler un outil
Au lieu de répondre directement en texte, le modèle retourne un bloc spécial tool_use : "J'appelle get_weather avec l'argument city='Paris'". Il a décidé lui-même qu'il avait besoin de cette information.
3
Ton code Python exécute vraiment l'outil
Tu interceptes la demande du LLM, tu appelles ta vraie fonction Python get_weather("Paris"), et tu obtiens le résultat : "22°C, ensoleillé".
4
Tu renvoies le résultat au LLM qui répond
Tu ajoutes le résultat dans l'historique. Le LLM peut maintenant formuler sa réponse finale : "Il fait 22°C à Paris aujourd'hui !". Ou il peut demander un autre outil si nécessaire.

        "Paris": "22°C, ensoleillé",
        "Lyon": "18°C, nuageux",
        "Marseille": "28°C, très ensoleillé"
    }
    return meteos.get(ville, f"Météo de {ville} indisponible")

def calculer(expression: str) -> str:
    try:
        resultat = eval(expression, {"__builtins__": {}})
        return str(resultat)
    except Exception as e:
        return f"Erreur : {e}"

# Associer le nom de l'outil à la fonction Python
MES_OUTILS = {
    "get_weather": get_weather,
    "calculer": calculer
}

# ── ÉTAPE 3 : La boucle agentique ──
def lancer_agent(question: str) -> str:
    """Lance l'agent sur une question et retourne la réponse finale."""

    messages = [{"role": "user", "content": question}]
    print(f"\n👤 Question : {question}")

    while True:  # on boucle jusqu'à avoir une réponse finale

        reponse = client.messages.create(
            model="claude-3-5-haiku-20241022",
            max_tokens=1024,
            tools=OUTILS,
            messages=messages
        )

        # Cas 1 : réponse textuelle finale → on a terminé
        if reponse.stop_reason == "end_turn":
            print(f"✅ Réponse finale : {reponse.content[0].text}")
            return reponse.content[0].text

        # Cas 2 : le LLM veut utiliser un outil
        if reponse.stop_reason == "tool_use":

            # Ajouter la décision du LLM à l'historique
            messages.append({"role": "assistant", "content": reponse.content})

            resultats_outils = []

            for bloc in reponse.content:
                if bloc.type == "tool_use":
                    print(f"🔧 Outil appelé : {bloc.name}({bloc.input})")

                    # Exécuter la vraie fonction Python
                    fonction = MES_OUTILS[bloc.name]
                    resultat = fonction(**bloc.input)

                    print(f"   → Résultat : {resultat}")

                    resultats_outils.append({
                        "type": "tool_result",
                        "tool_use_id": bloc.id,
                        "content": resultat
                    })

            # Renvoyer les résultats au LLM
            messages.append({"role": "user", "content": resultats_outils})

# ── Test ──
lancer_agent("Quel temps fait-il à Paris ? Et combien font 42 × 7 ?")
# 🔧 Outil appelé : get_weather({'ville': 'Paris'})
#    → Résultat : 22°C, ensoleillé
# 🔧 Outil appelé : calculer({'expression': '42 * 7'})
#    → Résultat : 294
# ✅ Réponse finale : À Paris il fait 22°C et ensoleillé.
#    Et 42 × 7 = 294 !

CHAPITRE 07

RAG — La mémoire de l'IA

Le LLM ne connaît pas tes documents d'entreprise. Le RAG (Retrieval-Augmented Generation) lui permet de chercher dans tes données avant de répondre — sans le ré-entraîner.

RAGembeddingsvector databaseChromaDB

Le problème que le RAG résout

🚫

Sans RAG

"Résume notre rapport Q3 2024" → le LLM ne connaît pas ce document → il invente ou dit qu'il ne sait pas.

✅

Avec RAG

"Résume notre rapport Q3 2024" → le système cherche les passages pertinents dans la base de docs → le LLM résume avec les vraies données.

Comment ça marche — les 4 étapes

1
Découper les documents en morceaux (chunks)
Tes PDFs, Word, emails sont découpés en petits morceaux de ~500 mots avec un chevauchement. Pourquoi ? Parce qu'on ne peut pas mettre 500 pages dans un seul prompt.
2
Transformer chaque morceau en vecteur (embedding)
Un modèle d'embedding transforme chaque morceau de texte en un tableau de nombres (ex: [0.2, -0.5, 0.8, ...]). Des textes similaires donnent des vecteurs proches mathématiquement.
3
Stocker les vecteurs dans une base vectorielle
Ces vecteurs sont stockés dans une base de données spécialisée (ChromaDB, FAISS, Pinecone) qui permet de faire des recherches par similarité très rapidement.
4
À chaque question, chercher les morceaux pertinents
La question de l'utilisateur est convertie en vecteur. On cherche les 3-5 morceaux les plus proches (= les plus pertinents). On les injecte dans le prompt du LLM qui répond avec ces informations.
📡 Analogie réseau — DNS + cache

Le RAG c'est un peu comme le DNS avec cache. Tu ne mémorises pas toutes les adresses IP du monde — tu sais où chercher (le serveur DNS) et tu mets en cache ce dont tu as besoin. Le LLM ne connaît pas tous tes documents — il sait où chercher (la vector DB) et injecte ce qui est pertinent.

python — rag_simple.py
# pip install langchain langchain-anthropic chromadb sentence-transformers
from langchain.text_splitter import RecursiveCharacterTextSplitter
from langchain_community.vectorstores import Chroma
from langchain_community.embeddings import HuggingFaceEmbeddings
from langchain_anthropic import ChatAnthropic

# ── PHASE 1 : Indexation (à faire une seule fois) ──

# Tes documents (en vrai, tu lirais des fichiers)
documents = [
    """Notre rapport Q3 2024 montre un chiffre d'affaires
    de 2,5 millions d'euros, en hausse de 15% par rapport à Q2.
    Les produits SaaS représentent 70% des revenus.""",
    """L'équipe IT a déployé une nouvelle infrastructure réseau
    en septembre 2024. Le temps de latence moyen est passé de
    45ms à 12ms grâce au nouveau SDN.""",
    """Les objectifs Q4 2024 sont : augmenter les ventes de 20%,
    lancer 2 nouveaux produits, et réduire les coûts de 10%."""
]

# Découper en petits morceaux
splitter = RecursiveCharacterTextSplitter(
    chunk_size=300,    # taille d'un morceau en caractères
    chunk_overlap=50   # chevauchement pour ne pas couper les idées
)
morceaux = splitter.create_documents(documents)
print(f"{len(morceaux)} morceaux créés")

# Créer les embeddings et stocker dans ChromaDB
embeddings = HuggingFaceEmbeddings(model_name="all-MiniLM-L6-v2")
base_vectorielle = Chroma.from_documents(
    documents=morceaux,
    embedding=embeddings,
    persist_directory="./ma_base"  # sauvegardé sur disque
)
print("✅ Base vectorielle créée !")

# ── PHASE 2 : Répondre aux questions ──
llm = ChatAnthropic(model="claude-3-5-haiku-20241022")

def poser_question_sur_docs(question: str) -> str:
    """Cherche dans les documents et répond avec les vraies données."""

    # Trouver les 2 morceaux les plus pertinents
    morceaux_pertinents = base_vectorielle.similarity_search(question, k=2)
    contexte = "\n\n".join([m.page_content for m in morceaux_pertinents])

    # Construire le prompt avec le contexte injecté
    prompt = f"""Réponds à la question en utilisant UNIQUEMENT
le contexte fourni. Si la réponse n'est pas dans le contexte,
dis-le clairement.

Contexte :
{contexte}

Question : {question}"""

    reponse = llm.invoke(prompt)
    return reponse.content

# Test
print(poser_question_sur_docs("Quel est le chiffre d'affaires du Q3 ?"))
# → "Le chiffre d'affaires Q3 2024 est de 2,5 millions d'euros..."

CHAPITRE 08

LangChain — le framework IA

LangChain est la boîte à outils standard pour les projets IA en Python. Au lieu de tout coder à la main, il te fournit des briques prêtes à l'emploi.

LangChainLCELchainprompt template

Pourquoi LangChain ?

🔩

Sans LangChain

Tu codes toi-même la gestion de l'historique, les retries, le parsing JSON, la construction des prompts, l'intégration avec différents LLMs…

🚀

Avec LangChain

Tout ça est déjà fait. Tu assembles des "chains" comme des Legos. Tu te concentres sur la logique métier, pas sur la plomberie.

Le concept de "chain" — les pipes Python

LangChain utilise l'opérateur | (comme les pipes Unix !) pour connecter des étapes. La sortie d'une étape devient l'entrée de la suivante.

python — langchain_bases.py
from langchain_anthropic import ChatAnthropic
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser

# Initialiser le modèle
llm = ChatAnthropic(model="claude-3-5-haiku-20241022")

# ── Exemple 1 : Chain simple de résumé ──

# Template de prompt avec une variable {texte}
prompt_resume = ChatPromptTemplate.from_messages([
    ("system", "Tu es un expert en résumé de texte. Sois concis et clair."),
    ("human", "Résume ce texte en 3 points clés :\n\n{texte}")
])

# La chain : prompt → LLM → parser de texte
# C'est comme : cat fichier.txt | grep "..." | sort
chain_resume = prompt_resume | llm | StrOutputParser()

# Utilisation
resultat = chain_resume.invoke({
    "texte": "Le BUT RT forme des techniciens en réseaux et télécommunications..."
})
print(resultat)  # → "1. Formation technique... 2. ..."


# ── Exemple 2 : Sortie JSON structurée ──
from pydantic import BaseModel

class Classification(BaseModel):
    categorie: str        # "bug", "question", "feature"
    priorite: str         # "haute", "moyenne", "basse"
    resume: str           # résumé du problème

# with_structured_output force le LLM à respecter le schéma
llm_structure = llm.with_structured_output(Classification)

prompt_classif = ChatPromptTemplate.from_messages([
    ("system", "Tu es un assistant de support technique."),
    ("human", "Classe ce ticket : {ticket}")
])

chain_classif = prompt_classif | llm_structure  # pas de parser ici

ticket = chain_classif.invoke({
    "ticket": "L'application crash au démarrage depuis la mise à jour"
})
print(ticket.categorie)  # "bug"
print(ticket.priorite)   # "haute"
print(ticket.resume)     # "L'application ne démarre plus..."


# ── Exemple 3 : Traiter plusieurs items en parallèle ──
tickets = [
    "Mon app crash",
    "Comment changer mon mot de passe ?",
    "Il manque un bouton d'export"
]

# batch() traite tout en parallèle automatiquement
resultats = chain_classif.batch(
    [{"ticket": t} for t in tickets],
    config={"max_concurrency": 3}
)
print([r.categorie for r in resultats])
# ["bug", "question", "feature"]

CHAPITRE 09

Écrire de bons prompts

La qualité de la réponse d'un LLM dépend directement de la qualité du prompt. Voici les techniques qui font vraiment la différence, illustrées avec des exemples concrets.

system promptfew-shotchain-of-thoughtformat

Les 5 règles d'or

1. Être précis et explicite ▼

Le LLM ne lit pas dans tes pensées. Si tu veux 3 points, dis "3 points". Si tu veux du JSON, dis "JSON". Si tu veux du français, dis "en français".

❌ prompt vague
"Résume ce texte."
✅ prompt précis
"Résume ce texte en EXACTEMENT 3 points sous forme de liste.
Chaque point doit faire 1 phrase maximum. Réponds en français."
2. Donner un rôle dans le system prompt ▼

Le system prompt, c'est l'instruction permanente que reçoit le modèle avant tout. C'est là que tu lui donnes son rôle, ses règles et le format de sortie attendu.

exemple de system prompt efficace
system = """Tu es un assistant expert en infrastructure réseau
pour une équipe de techniciens BUT RT.

TES RÈGLES :
- Réponds TOUJOURS en français
- Utilise des termes techniques précis
- Si tu ne sais pas, dis "Je ne suis pas certain de..."
- Ne dépasse jamais 200 mots par réponse
- Si on te demande du code, utilise des blocs ```bash```"""
3. Montrer des exemples (few-shot) ▼

Montrer 2-3 exemples entrée/sortie améliore drastiquement la précision, surtout pour des formats custom. Le LLM comprend mieux "ce genre de chose" que "fais X".

exemple few-shot
prompt = """Classe l'anomalie réseau en : CRITIQUE, MAJEURE, MINEURE.

Exemple 1 :
Anomalie : "Coupure du lien WAN principal depuis 5 minutes"
Classification : CRITIQUE

Exemple 2 :
Anomalie : "Latence élevée sur un switch secondaire"
Classification : MAJEURE

Exemple 3 :
Anomalie : "Un port inutilisé en état 'err-disabled'"
Classification : MINEURE

Maintenant classe celle-ci :
Anomalie : "{anomalie}"
Classification :"""
4. Demander de réfléchir étape par étape ▼

Pour des tâches complexes, "réfléchis étape par étape" améliore vraiment la qualité. Le LLM vérifie son propre raisonnement avant de répondre.

chain-of-thought
prompt = """Analyse cette panne réseau.

Symptômes : Les utilisateurs du bâtiment B n'ont plus accès
au réseau depuis 10 minutes.

Raisonne étape par étape :
1. Quelles sont les causes probables ?
2. Quel équipement vérifier en premier ?
3. Comment diagnostiquer rapidement ?

Donne ensuite un plan d'action concis."""
5. Forcer le format de sortie ▼

Si tu dois parser la réponse dans ton code, force le LLM à utiliser un format exact. Sinon il peut varier entre les appels et ton parser plante.

forcer JSON
prompt = """Extrais les informations suivantes du ticket.
Réponds UNIQUEMENT en JSON valide, sans aucun texte autour,
sans backticks markdown.

Format attendu :
{"equipement": "...", "symptome": "...", "urgence": "haute|moyenne|basse"}

Ticket : {ticket}"""

CHAPITRE 11

Réussir son stage

Les compétences techniques ne font pas tout. Voici les conseils pratiques sur le comportement en entreprise, comment être "force de proposition", et les erreurs à éviter absolument.

soft skillscommunicationinitiativeerreurs à éviter

"Force de proposition" — c'est quoi concrètement ?

C'est dans ta fiche de stage. Ça ne veut pas dire "avoir toujours raison" ou "avoir des idées brillantes". Ça veut dire :

💡

Proposer des idées

En réunion ou sur Slack : "J'ai vu qu'on pourrait utiliser X pour ce problème, est-ce que ça serait utile ?" — Même une idée rejetée montre que tu réfléchis.

❓

Poser de bonnes questions

"J'ai pensé à faire X avec Y — est-ce le bon choix ?" plutôt que "qu'est-ce que je fais ?". Montre que tu as réfléchi avant de demander.

🧪

Prototyper vite

Faire un petit proof-of-concept en 2h pour valider une idée, le montrer à l'équipe. Concret > théorique.

📣

Communiquer l'avancement

"J'ai fini X, je commence Y, je bloque sur Z depuis 1h" — sans qu'on te demande. Proactive communication.

Les erreurs classiques des stagiaires — à éviter

❌ Rester bloqué en silence trop longtemps ▼

Règle d'or : pas plus de 2h bloqué sans demander de l'aide. Les développeurs seniors préfèrent t'aider 5 minutes maintenant plutôt que de te voir perdre 2 jours. Quand tu demandes, explique ce que tu as déjà essayé et le message d'erreur exact.

❌ Ne pas lire le message d'erreur jusqu'au bout ▼

Les tracebacks Python sont longs mais la vraie erreur est tout en bas. Lis la dernière ligne. "AttributeError: 'NoneType' object has no attribute 'text'" → tu essaies d'accéder à .text sur None → la réponse LLM était None → il y a eu une erreur d'API. Lis. L'erreur. Jusqu'au. Bout.

❌ Committer une clé API ▼

Si tu commit une clé API sur GitHub, même privé : 1) elle est considérée comme compromise, 2) tu dois en générer une nouvelle immédiatement, 3) prévenir ton tuteur. C'est une erreur qui arrive même aux pros — l'important c'est le réflexe de toujours mettre les clés dans .env avec .gitignore.

❌ Trop grosse PR d'un coup ▼

Ne code pas 3 jours entiers puis envoie une PR avec 50 fichiers changés. Fais des petites PRs fréquentes avec des changements cohérents. Plus facile à reviewer, plus facile à déboguer si quelque chose casse.

❌ Attendre la fin du sprint pour dire qu'on est en retard ▼

Si une tâche prend plus longtemps que prévu, le dire dès que tu le réalises — pas le dernier jour. "J'avais estimé 2 jours, c'est plus complexe que prévu, il me faudra 4 jours" est toujours préférable à un retard surprise.

❌ Être défensif en code review ▼

La code review n'est pas une critique personnelle. La bonne réponse c'est "Merci, je vais corriger" ou "Je ne comprends pas encore — peux-tu m'expliquer ?". Pas "mais ça marche quand même !" ou "c'est la façon dont je l'ai toujours fait".
